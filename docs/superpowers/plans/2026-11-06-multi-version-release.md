# 固定 release 分支与多版本发布清单实施计划

## 范围与契约

仅修改 data-platform-operators。使用固定 develop → release → main；同一时刻只准备一轮 release。算子版本独立于分支。新清单为 schemaVersion 3，components 数组以 (code, buildVersion) 唯一，发布线各自累计快照；正式同版本不同摘要拒绝。每次发布后清单不可变，保留原始构建提交、仓库摘要和父清单。

ci/release-versions.yaml 替换 active-versions.json，包含全部允许正式发布的精确版本；当前纳入四个 v4.0.1 与 B04 v5.0.0。develop 验证所有版本；release/main 按发布范围及显式兼容组合验收，兼容组合不扩大发布资格。历史已发布版本从源目录或范围移除后仍保留清单及交付记录。源码、wheel、容器逐版本隔离；镜像仅按已验收摘要晋级，main 保留手动发布。

v3 使用独立 OCI artifactType、layer media type 和 v3 标签。历史 v2 只读，不重写。首次 v3 汇总同发布线已验证 v2 历史（不可仅取最新），校验来源/祖先/摘要/管线编号；正式历史同版本冲突失败，候选按流水线顺序保留各版本最近记录。裸 release 不继承不同旧发布线的未发布候选。保留旧 release/v* 的只读解析供历史追溯；生产写入口只接受 develop/release/main。

平台代码不修改。交接文档列出 v3 发现/解析、数组多版本、注册身份、幂等冲突、历史补全、候选隔离和精确版本调用。平台消费方适配未验证前不触发正式 v3 发布。

## 任务与验收

1. v3 编解码与历史读取：先建立失败测试，再实现类型与分支校验、确定性 OCI 封装、v2 原字节读取和多版本索引；验证双版本、重复、非法版本、类型错配、历史累计与冲突。
2. 多版本计划和交付：替换发布范围；保留历史、不隐式发布测试辅助版本、允许同编码多个版本；按源/wheel/容器/组合复用，正式版本冲突、部分同步失败和重试保持原门槛。
3. CI 与文档：固定分支路由、保护分支入口、标签、回执；更新 README/CONTRACT/AGENTS/开发指引/CI 文档，新增平台交接规范、v3 示例和机器校验。
4. 验收：通用 CI 全套、实际仓库五版本规划、v3/v2 历史与失败路径集成验证、CI Lint、独立全分支评审。只涉及 CI，不改算子业务或 SDK。远端分支切换需先确认旧 release 分支无未合并内容，保留旧提交与 MR 证据，不覆盖发布产物。

## 共同约束

冻结计划摘要、生产作业身份、原生失败重试与公网 ACR 核验不变。权限/网络/摘要错误不得当作无历史。全量历史扫描必须有明确上限，超过上限失败而非静默截断。并发更新检查与发布串行锁保留；不修改平台项目或全局 GitLab 设置。

## 通用命名与参考源码

测试参考目录统一为 `tests/fixtures/pretraining_data_cleaning_reference/`，同步流程声明、加载路径及临时容器名称。29 个固定上游文件只移动目录，逐文件 SHA-256 核对不变；内部 `stage_b_mcap_v4` 包名和来源记录保持原样，不将来源版本词用于本仓通用 CI 命名。
